# 8h-probe

**導入數位工具卡住了？先一起弄清楚。** 副標「AI 可行性驗證」。

用 8 小時的總投入，在 4–6 週內，協助一個小型組織弄清楚一件卡住的事：**走不走得通、該怎麼走。** 用 AI 或不用 AI 都算答案。

## 這是什麼

- **時間投入**：總計 8 小時，分散在 4–6 週內。這是總投入，包含 kickoff 會議、實作、交付說明會議、期間所有溝通。
- **價格**：單案 NT$20,000，整案計價，不計時。開場會議前付四成，收尾後付六成。
- **交付物**：1 個可運行的 POC，附一份界線說明——哪些可以放心自己用、自己改；哪些一旦碰到個資、開始對外服務、或變成每天依賴的工具，就值得把工程師、設計師這類專業角色拉進來。POC 是概念驗證，不是可上線的系統——要撐得起實際使用人數與長期維護，通常還需要幾個月的實作。過程中可隨時調整方向，時間用完即停止。結束時會落在三種結局之一：可以直接用、方向對但還要打磨、或確認該由組織內部接手。
- **驗證的對象**：除了那件事本身，也同時驗證這件事最關鍵、最不確定的那一段走不走得通，以及這樣的合作方式適不適合這個組織。
- **流程**：一次 kickoff 會議 → 定期會議＋實作 → 收尾交付 → 一篇公開 write-up。
- **檔期**：每季至多接一個案子。

## 關於你們的資料

驗證通常只需要去識別化的樣本，不需要完整的正式資料。姓名、電話、身分證字號、金額這類欄位，可以先置換或移除再給我。範圍在開場會議談定，probe 結束後我這邊的副本一併刪除。

如果連去識別化都做不到，那本身也是一個要先解決的問題，我們可以在開場會議一起看。

## 不做什麼

- 不做市場分析
- 不做溝通策略、公關、推廣規劃
- 不做交付後的維運、代管、長期陪跑
- 沒有交付後的修改回合（過程中可修改，時間用完即停止）

## 收案準則

- 有單一決策者，能當場拍板（8 小時節奏緊湊，常需當場決定下一步）
- 已有可用的既有資料
- 手上有一件具體卡住的事，不是「聽說 AI 很厲害」的階段。需求發散可以，收斂本來就是這 8 小時的一部分

## 超時怎麼辦

若探測過程發現問題規模明顯超出時間上限，我會即時告知，且不自行延長；剩餘時間會拿來整理「8 小時之後如何繼續」——哪些已確認、哪些未驗證、可行的下一步。這是規格的一部分，不是失敗。

## 如果答案是「不需要 AI」

有時候驗證到一半會發現，這件事用一般的軟體開發、甚至只是改一張表單就能解決，不需要 AI。這種情況我會直接說，並且把該怎麼做、大概要多少工的判斷交給你們。

這一樣是有效的交付。「這件事不需要 AI」跟「這件事比想像中大」一樣，都是值得花錢知道的答案——而且它替你們省下的，比一套做出來的系統多。

## 這個 repo 是什麼

案例紀錄的累積體，附帶服務說明。目的不是規模化或行銷，而是：

1. 認識更多元的使用情境
2. 理解小型組織在導入 AI 時實際卡在哪裡

因此這裡會記錄**成案與未成案**兩種紀錄。婉拒紀錄一律匿名化到組織型態層級，不出現可識別資訊。
