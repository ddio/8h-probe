# 8h-probe

用 8 小時的總投入，在 4–6 週內，協助一個小型組織驗證一件事：**AI 能不能做他們想做的那件事。**

## 這是什麼

- **時間投入**：總計 8 小時，分散在 4–6 週內。這是總投入，包含 kickoff 會議、實作、交付說明會議、期間所有溝通。
- **價格**：單案 NT$20,000，整案計價，不計時。
- **交付物**：1 個可運行的 POC。過程中可隨時調整方向，時間用完即停止。
- **流程**：一次 kickoff 會議 → 定期會議＋實作 → 收尾交付 → 一篇公開 write-up。

## 不做什麼

- 不做市場分析
- 不做溝通策略、公關、推廣規劃
- 不做交付後的維運、代管、長期陪跑
- 沒有交付後的修改回合（過程中可修改，時間用完即停止）

## 收案準則

- 有單一決策者，能當場拍板
- 已有可用的既有資料
- 問題已初步成形（不是「聽說 AI 很厲害」的階段）

## 超時怎麼辦

若探測過程發現問題規模明顯超出時間上限，我會即時告知，且不自行延長；剩餘時間會拿來整理「8 小時之後如何繼續」——哪些已確認、哪些未驗證、可行的下一步。這是規格的一部分，不是失敗。

## 這個 repo 是什麼

案例紀錄的累積體，附帶服務說明。目的不是規模化或行銷，而是：

1. 認識更多元的使用情境
2. 理解小型組織在導入 AI 時實際卡在哪裡

因此這裡會記錄**成案與未成案**兩種紀錄。婉拒紀錄一律匿名化到組織型態層級，不出現可識別資訊。

## 目錄結構

- `docs/cases/` — 案例紀錄（成案與婉拒）
- `docs/research/` — 市場研究
- `docs/posts/` — 社群貼文草稿與定稿
- `docs/service-page/` — 服務說明頁發想
- `docs/tools/` — 小工具發想
