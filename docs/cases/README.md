# 案例紀錄

每一次服務的公開紀錄。組織名稱與可識別的細節依對方的意願匿名，範圍在開始前談定。

## 成案紀錄：前後兩篇

**前篇（結案前後）**以自由文字為主體，寫這個案子的**收穫與檢討**，並對照[文獻回顧](../research/)：

- 驗證了研究中已有的哪些現象
- 遇到哪些文獻裡還沒看到的狀況
- 哪裡做得不好、對服務規格的校準是什麼

開頭以敘述帶出案子速寫，供跨案比較：組織型態與規模、決策者結構、既有資料狀態、原始需求（他們原本以為 AI 能做什麼）、實際卡在哪一層、時程、產出。速寫是背景，不是主體，不另立一節。

**後篇（結案後數個月）**做後追蹤——這是區分「示範成功」與「導入成功」的唯一證據。不是每個案子都有 POC，有 POC 也不一定適合用「三個月後還有沒有人在用」來問（它可能被正式版取代，或本來就只為回答一個問題），所以追蹤項目由前篇依個案訂出。

## 婉拒紀錄欄位

組織型態與規模、決策者結構、既有資料狀態、他們原本以為 AI 能做什麼，加上：卡在三條收案準則的哪一條、當時的實際狀況。

## 具名與匿名

婉拒紀錄一律匿名化到組織型態層級（例如「中部、5 人以下、社福領域」），不出現組織名稱、聯絡人或其他可識別資訊。成案紀錄的組織名稱需經對方同意才公開，且刊出前由對方審閱全文。
